2. Dataset Identification
2.1 Problem Statement
Briefly describe the problem addressed in the selected internship domain:
In the FinTech and banking domain, credit approval systems rely on machine learning models to assess loan applicant default risk. In dynamic economic conditions, interest rate fluctuations, inflationary pressure, and consumer financial stress cause distribution shifts in applicant profiles (Covariate Shift) and change the underlying relationship between applicant characteristics and default likelihood (Concept Drift). If unmonitored, deployed models suffer silent performance decay, leading to increased loan default losses or erroneous credit rejections.

2.2 Dataset Details
Dataset Name: FinTech Consumer Credit Default Risk Monitoring Dataset
Dataset Source: Synthetically generated based on empirical Federal Reserve & LendingClub macroeconomic credit distributions (implemented via reproducible generator in src/data_generator.py).
Number of Records: 17,500 total records:
- Baseline Reference Set: 10,000 records
- Production Batch 1 (In-Distribution Stable): 2,500 records
- Production Batch 2 (Covariate Shift / Data Drift): 2,500 records
- Production Batch 3 (Concept & Prior Probability Drift): 2,500 records
Important Features:
- 10 Numerical: applicant_age, annual_income, credit_score, debt_to_income_ratio, loan_amount, interest_rate, employment_length_years, open_credit_lines, revolving_utilization_rate, delinquencies_2yrs.
- 3 Categorical: home_ownership (RENT, MORTGAGE, OWN), loan_purpose (debt_consolidation, credit_card, small_business, home_improvement, education), employment_type (salaried, self_employed, contract).
Target Variable (if applicable): loan_default (Binary: 0 = Non-Default / Paid, 1 = Default / Charged-Off)
Use Case Category: ML / Supervised Classification / Production MLOps Monitoring

2.3 Dataset Selection Rationale
Explain why the dataset is relevant to the selected problem:
Credit default risk modeling in digital banking provides an authentic testbed for MLOps drift detection. Continuous features such as interest rates and debt-to-income ratios directly reflect monetary policy changes, while ground-truth default outcomes have an inherent delayed feedback loop (loans take months to default). Thus, detecting covariate shift and real-time prediction output drift allows financial institutions to take proactive measures before realizing significant balance-sheet losses.












3. Drift Scenario and Detection Method
3.1 Drift Type
Identify the relevant drift type: Data Drift / Concept Drift / Prediction Drift:
All three drift types are systematically modeled and monitored:
1. Data Drift (Covariate Shift): Macroeconomic stress shifting feature distributions P(X) (higher interest rates, higher DTI, elevated revolving utilization) while risk logic P(Y|X) remains unchanged.
2. Concept Drift: Structural shift in relationship P(Y|X) where small business and self-employed borrowers default at higher rates despite standard credit scores.
3. Prediction Drift & Label Drift: Divergence in model prediction probabilities P(Y_hat) and prior default rates P(Y).

3.2 Reference and Current Data
Briefly describe the datasets or model outputs compared, including whether the drift is naturally observed or simulated:
- Reference Data: Baseline dataset (10,000 records) representing stable macroeconomic credit conditions (default rate ~35%).
- Current Data: 3 sequential simulated production cohorts (2,500 records each):
  1. Batch 1: In-distribution stable production traffic (simulated from identical baseline parameters).
  2. Batch 2: Simulated covariate shift (simulating rate hikes: interest rates shifted from 11.5% to 17.5%, DTI and utilization elevated).
  3. Batch 3: Simulated concept drift (economic disruption causing severe label drift and structural default relationship shift).

3.3 Detection Method
Method / Statistical Test / Tool Used:
- Population Stability Index (PSI): Segmenting continuous features and predicted probabilities into 10 quantile bins based on reference data.
- Two-Sample Kolmogorov-Smirnov (KS) Test: Non-parametric comparison of empirical cumulative distribution functions (eCDFs).
- Chi-Square Goodness of Fit Test: Frequency divergence across categorical attributes.
- Prediction Drift & Label Delta: Measuring PSI on model output probabilities P(Y_hat) and absolute difference in positive class frequencies |P(Y_ref) - P(Y_prod)|.
- Tool: Custom statistical drift engine (src/drift_engine.py) integrated with MLflow Tracking Server.
Features or outputs analyzed:
All 13 input features, dataset-level drift ratio, model output predicted probabilities P(Y_hat), and ground-truth default target rates P(Y).
Detection threshold or criteria, if applicable:
- PSI Criteria: PSI < 0.10 (Stable / No action); 0.10 <= PSI < 0.25 (Moderate shift / Warning); PSI >= 0.25 (Significant drift / Trigger Retraining).
- KS-Test: Significance level alpha = 0.05 (drift flagged if p-value < 0.05).
- Dataset Drift Trigger: Flagged if >= 30% of features exhibit drift OR prediction probability PSI >= 0.25.

4.2 Interpretation
Explain what the findings mean for the selected internship domain:
In FinTech credit scoring, Batch 1 validates that normal variations within expected demographics do not destabilize model scoring. In Batch 2, macroeconomic shifts dramatically alter customer borrowing profiles; while the model's raw F1 remained high due to class surge, the prediction probabilities drifted drastically (PSI 2.9645), creating miscalibrated default probabilities. In Batch 3, structural disruptions changed default correlations, creating heavy label drift (56.7% surge). Automated detection ensured that silent model decay was identified before loan portfolios suffered severe losses.
